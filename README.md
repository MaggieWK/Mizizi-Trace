# Miziziroots — Mizizi Trace

**Redefining who controls value creation.**

Mizizi Trace is an origin-verification, impact-reporting, and export-compliance tool for agrifood and circular-economy ventures. It generates a different, audience-appropriate report from the same underlying order and farmer data — instead of one dense document nobody but a compliance officer can read.

> **Status: working prototype.** This is a single-file, front-end demo — no backend, no live data connections, no persistence between sessions. It's built to demonstrate the product and the underlying methodology, not to run in production yet. See [Roadmap](#roadmap) for what's next.

## What it does

One order. Four completely different outputs, depending on who's reading:

| Audience | What they see |
|---|---|
| **Farmer / Cooperative** | Plain-language season summary, cumulative delivery and payment record, no jargon. English or Kiswahili, selectable, with a bilingual downloadable report. |
| **Consumer** | A personal, story-first impact receipt for one purchase — units, carbon avoided, an impact tier. |
| **Procurement / Distributor** | Order-level volume, the actual compliance document (EU Due Diligence Statement or Gulf halal/traceability preview), and a checklist of required export documents. |
| **Stakeholder / Investor** | Full IRIS+ and GHG Protocol-referenced detail — climate, sequestration, circularity, water, and social metrics, each tagged with the standard it's measured against, plus SDG alignment. |

A **materiality intake** step at the top decides which impact categories apply to a given venture — nothing is assumed on by default. A venture only shows sequestration numbers if it actually runs reforestation/agroforestry, water numbers if it actually measures water, and so on.

## Standards referenced

- **GHG Protocol** (Product Life Cycle Standard) and **IRIS+** (GIIN) for climate and social metrics
- **Ellen MacArthur Foundation Material Circularity Indicator** for circularity claims
- **Higg Index** as the native standard when the venture's domain is textiles
- **Alliance for Water Stewardship (AWS) Standard** for water claims
- **EU Deforestation Regulation** (Regulation (EU) 2023/1115, as amended by Regulation (EU) 2025/2650) for EU market compliance
- **UAE Federal Decree-Law No. 2 of 2024** for Gulf market traceability

All figures generated by the tool are **indicative** unless stated otherwise, and every compliance/impact section says so explicitly in the UI. Real emission factors, plot geolocation, and certification status must be independently verified before any figure is used externally — see [Known limitations](#known-limitations).

## Running it

No build step, no install. Two options:

1. **Locally:** download `index.html` and open it in any browser.
2. **Live, via GitHub Pages:** Settings → Pages → Deploy from branch → `main` → `/ (root)`. GitHub will serve `index.html` automatically at `https://<your-username>.github.io/miziziroots/`.

## Repository structure

```
miziziroots/
├── index.html              the tool itself (single file: HTML, CSS, JS)
├── config/                 reference data, mirrors what's currently hardcoded in index.html
│   ├── commodities.csv
│   ├── markets.csv
│   ├── export_documents.csv
│   └── origin_sites.csv
├── docs/
│   └── developer-brief.md  scoped tasks for turning this into a connected, persistent tool
├── CHANGELOG.md
└── README.md
```

The `config/` CSVs are not yet connected to `index.html` — they document the target shape for when the tool reads from a real data source instead of hardcoded arrays (see Roadmap).

## Known limitations

- No backend — nothing entered into the tool is saved anywhere.
- The "unlock full report" email gate is a UI pattern only; no email is actually sent or stored.
- Climate, water, and circularity constants are fixed placeholder values, not live-sourced.
- Origin sites are sample data, not real farmer/cooperative records.
- Kiswahili translations are a good-faith draft, not reviewed by a native speaker.

## Roadmap

See [`docs/developer-brief.md`](docs/developer-brief.md) for the specific, scoped tasks: connecting `config/` to a real spreadsheet source, adding persistence for farmer/order records, wiring the email gate to a real Klaviyo form, and connecting climate figures to a live emission-factor source.
